SAST-PY-001 Extraction API has no authentication

FieldDetail
Canonical IDCAN-PY-001
SeverityMedium
CVSS6.5 CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:L/A:N
StatusOpen
SAST resultConfirmed in source
DAST resultConfirmed
ConfidenceHigh
CWE / OWASPCWE-306 Missing Authentication for Critical Function. OWASP API Security Top 10 API2; OWASP Top 10 A01 Broken Access Control
ComponentFastAPI app in app.py, published by nginx location /extract/
Locationapp.py:136-147 and route handlers at app.py:44377, 46231, 47531, 47666, 47708

Description

Every application route is registered without a FastAPI dependency, API-key check, or authentication middleware. The HTTP middleware only counts in-flight requests. nginx location /extract/ proxies to 127.0.0.1:8001 with no auth_request and no allow/deny rule. Interactive documentation is left at the FastAPI defaults.

Root cause

Routes trust the network path. The application does not authenticate the caller.

Preconditions

Network reachability of port 8001 or the nginx /extract/ location. No account is required.

Impact

Any client who can reach port 8001 or https://zydus-py.mediola.in/extract/ can call extraction, read operational health, and download the API schema. Laravel authorization, if any, is not enforced here. A customer invoice was not submitted during this assessment.

Evidence

app.py constructs FastAPI() with no docs_url override and adds only CORSMiddleware plus an in-flight counter. Handlers split_and_extract_invoices, test_extract, extract_pod_grn_endpoint, and extract_sales_statement_endpoint declare no security dependency. Live OpenAPI securitySchemes is null.

Remediation

Require a shared credential or mutual TLS between the Laravel application and this service, and reject missing credentials with HTTP 401. Restrict the nginx location to the application servers. Disable /docs, /redoc, and /openapi.json on the public vhost.

Verification

After the control is added, repeat an unauthenticated GET /extract/docs and an empty POST /extract/split-and-extract. Both should be HTTP 401 or HTTP 403, and the public vhost should not serve the schema.

Limitations

Cross-tenant document access was not attempted. Availability impact from repeated calls was not measured.

SAST-PY-002 split_raw_url is fetched without a destination allow list

FieldDetail
Canonical IDCAN-PY-002
SeverityMedium
CVSS6.5 CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:L/A:N
StatusOpen
SAST resultConfirmed in source
DAST resultNot performed
ConfidenceHigh for the code path. Runtime behavior was not re-executed.
CWE / OWASPCWE-918 Server-Side Request Forgery. OWASP API Security Top 10 API7; OWASP Top 10 A10 SSRF
ComponentPOST /split-and-extract and POST /extract-pod-grn
Locationapp.py:44539-44546 and app.py:47599-47602

Description

When a caller omits the upload file and supplies split_raw_url, both handlers pass that value to requests.get with a 120-second timeout and no scheme, host, port, or redirect allow list. The downloaded bytes are then treated as the document to parse. The routes are unauthenticated.

Root cause

The form field is used as a request URL. requests follows redirects by default.

Preconditions

Reachability of the unauthenticated route. No live fetch was performed in this assessment.

Impact

A reachable caller can cause the server to issue an HTTP GET to a destination it names, including addresses the server can reach. This assessment did not send a URL and did not request cloud-metadata or internal addresses. Impact beyond the code path was therefore not demonstrated.

Evidence

split_and_extract_invoices calls requests.get(split_raw_url, timeout=120) and writes response.content to the temp file. extract_pod_grn_endpoint uses the same call and then parses the body. No urlparse host check precedes either call.

Remediation

Remove arbitrary URL fetch, or accept only HTTPS URLs on an explicit storage-host list. Do not follow redirects onto a different host. Require authentication before any fetch. Return a generic error instead of the client exception text.

Verification

On a non-production instance, submit a URL outside the allow list and confirm the service does not open a connection and does not echo resolver or connection errors. Confirm an allow-listed storage URL still works for the Laravel caller.

Limitations

A server-side fetch was not sent. Cloud-metadata and internal-network destinations were not requested. A September 2026 assessment recorded a loopback fetch; that test was not repeated and is not used as this assessment's proof.

SAST-PY-003 Caller-supplied blob container and path are used with the service credential

FieldDetail
Canonical IDCAN-PY-003
SeverityMedium
CVSS6.5 CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:L/A:N
StatusOpen
SAST resultConfirmed in source
DAST resultNot performed
ConfidenceHigh for the code path. Storage access was not demonstrated.
CWE / OWASPCWE-284 Improper Access Control. OWASP API Security Top 10 API1 Broken Object Level Authorization
Componentblob_container, split_raw_blob_path, target_invoices_blob_folder; upload_split_pdf_to_blob
Locationapp.py:44506-44557, app.py:44296-44343, app.py:47609-47613

Description

blob_container overrides the configured container. split_raw_blob_path is passed to download_blob().readall() with the process Azure credential. target_invoices_blob_folder becomes the upload prefix, and upload_blob is called with overwrite=True. A successful upload returns a read SAS built from the account key, valid for 24 hours. The same fields are accepted by /extract-pod-grn and by the live /extract-sales-statement handler.

Root cause

Storage identity is the service account. Object names and the container name come from the request, and the routes are unauthenticated.

Preconditions

Azure credentials are loaded in the process environment. A live storage call was intentionally not made.

Impact

If the reviewed code is the code that is loaded, a caller who can reach the route can name a blob to read and a prefix to write, then receive a read URL. This assessment did not read or write an Azure object. No customer blob access is claimed.

Evidence

container_name falls back to AZURE_CONTAINER_NAME only when blob_container is empty. get_blob_client(container=container_name, blob=split_raw_blob_path) is followed by download_blob().readall(). upload_split_pdf_to_blob builds blob_name from target_invoices_blob_folder and returns blob_client.url plus a read SAS.

Remediation

Ignore client container names. Authorize blob operations against a fixed container and a server-generated prefix. Do not return an account-key SAS to an anonymous caller. After authentication exists, prefer a short-lived user-delegation SAS.

Verification

On a non-production storage account, send a foreign container and blob name and confirm the API rejects them. Confirm a legitimate Laravel upload still lands in the server-chosen prefix and that the response does not contain an account-key SAS.

Limitations

No blob read, overwrite, or SAS URL was requested. Credential values were not recorded.

SAST-PY-010 Upload size and concurrency limits do not cover every extraction route

FieldDetail
Canonical IDCAN-PY-010
SeverityLow
CVSSNot scored Availability impact was not tested, so no CVSS score is assigned.
StatusOpen
SAST resultConfirmed in source and nginx configuration
DAST resultNot performed
ConfidenceHigh for the missing control. Low for availability impact, which was not measured.
CWE / OWASPCWE-770 Allocation of Resources Without Limits or Throttling. OWASP API Security Top 10 API4 Unrestricted Resource Consumption
Component/test-extract, /extract-sales-statement, /extract-pod-grn, nginx body size
Locationapp.py:139, app.py:234, app.py:44470, app.py:46231; nginx client_max_body_size 500M

Description

Request.max_body_size = 200MB is assigned on the Starlette Request class. That attribute is not implemented by the installed Starlette 0.45.3, so the assignment does not enforce a limit. After the bytes are read, the handlers log the size and do not reject it. /split-and-extract acquires a semaphore of MAX_CONCURRENT_REQUESTS, which is 1 in the live environment, with a queue timeout of 3600 seconds. /test-extract, /extract-sales-statement, and /extract-pod-grn do not acquire that semaphore. nginx allows a 500 MB body. No per-client rate limit was found. A load test was not performed.

Root cause

The body cap is not enforced in the application, and the single-flight gate is applied only to the primary route.

Preconditions

The control gap is visible in source. Resource exhaustion was intentionally not tested.

Impact

A small number of large or concurrent extraction calls can occupy the one worker. That outcome was not measured and is not claimed as an outage.

Evidence

Starlette Request has no max_body_size. Only split_and_extract_invoices calls request_processing_semaphore.acquire. The live environment reports MAX_CONCURRENT_REQUESTS=1.

Remediation

Enforce one authenticated size cap before OCR, on every extraction route, and align nginx with it. Put every extraction route on the same queue. Remove or firewall /test-extract.

Verification

Submit a body above the chosen cap and confirm HTTP 413 before OCR starts. Confirm /test-extract is absent or authenticated.

Limitations

No oversized body and no concurrent upload were sent. Rate limiting is therefore unverified as an effective control; the absence of an application limiter is confirmed by review.

Description

pip-audit 2.10.1, pointed at the production site-packages and not at a reinstall, reported 109 advisory records. De-duplicated identifiers total 70, across 12 packages. No advisory was exploited. Packages on the document path include pillow 11.1.0, python-multipart 0.0.20, starlette 0.45.3, pdfminer-six 20231228, PyPDF2 3.0.1, requests 2.32.3, and urllib3 2.7.0. The fix versions reported by the tool are in scans/pip_audit_summary.json. An earlier invocation that tried to re-resolve the freeze file failed on cffi==2.0.0 and was discarded.

Root cause

Installed packages are below fix versions reported by the advisory database on the day of the scan.

Preconditions

Advisory data was retrieved from the tool's default service on 22 October 2026.

Impact

Unknown until each advisory is compared with the code paths this service uses. This item is patch input, not a demonstrated breach.

Evidence

scans/pip_audit.json and scans/pip_audit_summary.json. Counts: 109 records, 70 unique identifiers, 12 packages.

Remediation

Upgrade in a test environment, starting with pillow, python-multipart, starlette, and the PDF libraries. Re-run pip-audit and retest invoice extraction. Do not upgrade the production environment as part of this assessment.

Verification

pip-audit against the same site-packages reports no advisories, or each remaining identifier is accepted with a written reason.

Limitations

Individual advisory CVSS scores were not revalidated. No exploit was run. Transitive packages were included because they are installed.

7. Remediation order

  • 1. Authenticate every extraction route and restrict nginx /extract/ to the Laravel servers. Disable public API documentation.
  • 2. Remove arbitrary URL fetch, or allow only named HTTPS storage hosts, and stop returning internal exception text.
  • 3. Ignore client container names and client blob prefixes. Stop returning an account-key SAS to anonymous callers.
  • 4. Change /var/www/html/.env to mode 600 and rotate the credentials that were world-readable.
  • 5. Bind the API to 127.0.0.1 so TLS and the nginx body limit cannot be bypassed.
  • 6. Remove in-flight file names and batch identifiers from unauthenticated health output.
  • 7. Replace reflected CORS with an explicit origin list. Add HSTS and hide server versions.
  • 8. Enforce one upload-size cap and one queue on every extraction route. Remove or protect /test-extract.
  • 9. Run the service as an unprivileged user. Align the Dockerfile with runner.py.
  • 10. Patch pillow, python-multipart, starlette, and the PDF libraries in a test environment, then retest extraction.

8. Retest

No remediation was applied and no retest was passed. Every record remains Open.

9. Limitations

  • The target is the live extraction process. Destructive, high-volume, and data-plane tests were not run.
  • No application account exists, so role and cross-account tests could not be performed. Object-level storage access was not executed.
  • Server-side URL fetch was not exercised. Cloud-metadata and internal-network destinations were not requested.
  • No synthetic or customer file was submitted, so MIME confusion, parser crashes, and processing timeouts were not measured at runtime.
  • Rate-limit effectiveness and off-box Internet exposure of port 8001 were not measured. The port answered on this host's own primary address, and the host firewall does not filter it.
  • Port 8000 is a separate listening process and was not assessed. nginx also maps ports 8002 and 8003; those ports were not listening.
  • The Laravel application was out of scope. A prior Python assessment dated 22 September 2026 was not treated as retest evidence.
  • Dependency advisories were not exploited and were not each converted into a vulnerability.

10. Disclaimer

This is a point-in-time review. An area with no finding was either reviewed or marked untested. Scanner alerts were triaged before acceptance.
